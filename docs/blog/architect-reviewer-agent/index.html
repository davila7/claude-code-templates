Architect Reviewer Agent for Claude Code: Review System Design Before You Refactor

Install the Architect Reviewer agent for Claude Code to evaluate system design, service boundaries, and technology choices with a read-only, risk-ranked architecture review.

5 min read
Claude CodeAgentsArchitectureSystem DesignCode Review

What is the Architect Reviewer Agent?

The Architect Reviewer is a Claude Code subagent from the development-tools category in Claude Code Templates. Where a code reviewer looks at individual files and functions, this agent evaluates the macro level: architectural patterns, service boundaries, technology choices, and how a system will evolve. It is a read-only agent (tools: Read, Grep, Glob), so it can inspect your codebase and design documents but never edits files or runs shell commands.

    A[Design docs and ADRs] --> B[Architect Reviewer]
    C[Codebase structure] --> B
    B --> D[Risk-ranked findings]
    D --> E[Verdict: Proceed or Revisit]

    style B fill:#F97316,stroke:#fff,color:#000

Key Capabilities

  • Architecture checklist (design patterns, scalability targets, technology choices, integration patterns, security, performance, technical debt, evolution path)
  • Grounded in real artifacts (ADRs, the C4 model, and fitness functions such as ArchUnit or Dependency Cruiser/madge to enforce rules in CI)
  • API and service contract review (versioning, backward compatibility, error envelopes, pagination, idempotency, REST vs GraphQL vs gRPC fit)
  • Structured output (every finding is tagged CRITICAL / HIGH / MEDIUM / LOW with Risk and Recommendation, followed by a summary and a verdict)
  • Honest about gaps (if scale targets or diagrams are missing, it asks instead of inventing numbers)

Installation

Install the agent with the Claude Code Templates CLI:

npx claude-code-templates@latest --agent development-tools/architect-reviewer

The CLI copies the agent file into your project's .claude/agents/ directory, where Claude Code picks it up automatically:

your-project/
├── .claude/
│   └── agents/
│       └── architect-reviewer.md    # ← Agent installed here
└── package.json

Subagents are Markdown files with YAML frontmatter (name and description are required; tools and model are optional). Project agents in .claude/agents/ can be committed so the whole team shares them; agents in ~/.claude/agents/ are available in all your projects.

Step-by-Step Workflow

Step 1: Gather the context

Point the agent at what exists: ADRs, a docs/architecture.md, diagrams, or just the repository layout. The agent will use Grep and Glob to inspect module boundaries and entry points rather than trusting documentation alone.

Step 2: Invoke the agent

Claude Code delegates automatically when your request matches the agent's description (it is marked for proactive use before major refactors), or you can name it explicitly:

claude

> Use the architect-reviewer agent to review our plan to split the monolith in /services into microservices. Check service boundaries and data ownership.

You can also type @ and pick the agent from the list, or start a whole session as the agent with claude --agent architect-reviewer.

Step 3: Read the risk-ranked findings

The agent returns findings in a fixed format, for example:

**[HIGH] Data architecture — orders and billing share one database**
Risk: schema changes in one service break the other; no clear data owner
Recommendation: give each service its own schema, expose data via API/events, record the decision in an ADR

> Architecture Review Summary: 8 areas reviewed, 0 CRITICAL, 1 HIGH, 2 MEDIUM, 1 LOW findings. Top risk: shared database. Verdict: **Proceed with changes**.

Step 4: Turn findings into guardrails

Ask the agent to recommend fitness functions for your stack, then implement them yourself (the agent is read-only):

> Which fitness functions would enforce the layering rules you found? Suggest concrete Dependency Cruiser rules for this repo.

Step 5: Hand off to specialists

When a review surfaces a concern outside its scope, the agent says so. Follow up with a code reviewer for implementation quality, a security auditor for deeper security architecture, or a performance engineer for load-testing the design.

When to Use It

  • Before a monolith-to-microservices migration
  • When choosing between a monolith, serverless, or containers for a new system
  • When coupling makes deploys and tests slow and you need a phased modernization plan (strangler fig, branch by abstraction)
  • Before committing to an API style or versioning strategy
Tip: the agent focuses on system-level design. For file-level quality, pair it with a code reviewer agent after the design is approved.
