# Improvement routing

Choose the narrowest surface that can prevent recurrence.

| Destination | Use when | Avoid when |
|---|---|---|
| Runtime behavior | The correction matters only now | It should survive the session |
| Skill | A reusable method, trigger, pitfall, or verification recipe changed | It is only a preference or project fact |
| Project instructions | A repository/project rule should guide future work | It applies only to one temporary task |
| User instructions | A stable cross-project preference or collaboration contract was learned | It exposes private task detail or will go stale |
| Durable memory | The host has verified memory and the fact is stable, compact, and expected to be remembered | Memory is generated state, the lesson is procedural, or the surface is unverified |
| Project documentation | Architecture, decisions, runbooks, or operational truth changed | It is only agent behavior guidance |
| Task/issue | Work remains and belongs in the normal tracker | The proposal is not approved |
| No durable change | The incident is local, covered, or low-signal | A repeated costly failure has no guard |

## Selection test

1. Will this still matter in a month? If no, keep it runtime-only.
2. Is it a fact, preference, procedure, or project decision? Route by type.
3. Who should inherit it: one task, repository, agent, or all work?
4. Does an existing surface already own it? Revise/consolidate instead of duplicating.
5. Can it be verified? If not, narrow the claim or mark it experimental.
6. Does the permanent context cost earn its place?

Prefer correcting the responsible source, then consolidating an existing rule, then one scoped instruction, then a skill procedure. Use durable memory only for stable facts/preferences on verified hosts. Create a new system only when no existing owner fits.

## User-side improvements

Allowed only when ambiguity is evidenced, the agent could not choose a safe default, the suggestion is optional and low-effort, the agent's default without it is stated, and the suggestion does not excuse incomplete execution or false reporting.

Bad: “Write a clearer prompt next time.”

Better: “Agent commitment: before a visual redesign, surface two directions. Optional user leverage: name a non-negotiable reference. Default: preserve the current brand and propose two bounded variants.”
