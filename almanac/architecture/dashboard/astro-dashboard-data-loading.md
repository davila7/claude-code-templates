Astro dashboard data loading is built around small static JSON artifacts generated by the catalog pipeline. The dashboard can still fetch the full `components.json`, but the primary list and search experiences use per-type slices and a flat search index so the browser does not need the whole catalog up front [@data-lib]. Detail pages then fetch raw component content only after the index record identifies the requested component [@detail-page]. The artifact producer is described in [Catalog Generation Pipeline](../catalog/catalog-generation-pipeline).

## Static Artifact Contract

`COMPONENTS_JSON_URL` defaults to `/components.json` and can be overridden with `PUBLIC_COMPONENTS_JSON_URL` [@constants]. The full index is cached in memory for five minutes by `fetchComponents()`, and server-side development mode first reads `public/components.json` from disk to avoid stale production data [@data-lib]. On server-side fetches, relative URLs are resolved against `import.meta.env.SITE` or `https://www.aitmpl.com`, because Node fetch requires an absolute URL [@data-lib].

The optimized artifacts come from `scripts/generate_components_json.py`. It emits `dashboard/public/components.json` without content or security metadata, `dashboard/public/components/{type}.json` per-type slices, `dashboard/public/search-index.json` for global search, and `dashboard/public/component-content/{type}/{slug}.json` for raw content [@catalog-generator]. `data.ts` mirrors that split with `fetchComponentsByType()`, `fetchSearchIndex()`, and `fetchComponentContent()` [@data-lib].

## Type Pages

The route `dashboard/src/pages/[...type].astro` prerenders the main component-type pages for skills, agents, commands, settings, hooks, MCPs, and loops [@type-page]. It validates the route parameter against known component types, chooses metadata for the active type, and mounts the React `ComponentGrid` island with `client:load` [@type-page].

`ComponentGrid` owns the active list state in the browser. It calls `fetchComponentsByType(activeType)`, which loads `/components/{type}.json`, keeps a five-minute cache per type, and returns an empty array on failure when there is no cached value [@component-grid] [@data-lib]. The grid then performs category filtering, text search, minimum-download filtering, sorting, pagination, cart updates, and view-mode state locally over that one type slice [@component-grid].

## Search Loading

Global search is lazy. `SearchModal` does not request search data until the modal is first opened, then calls `fetchSearchIndex()` and keeps the result for future searches [@search-modal]. The index contains only name, description, category, type, and path fields, matching the generator's `search-index.json` shape [@catalog-generator]. Search results navigate to `/component/{component.type}/{cleanPath(component.path)}` after stripping `.md` or `.json` from the path [@search-modal].

## Detail Pages

Component detail routes are dynamic, with `prerender = false`, because they resolve the requested component at request time from the catalog index and then load raw content on demand [@detail-page]. The page normalizes the route type to a plural key, finds the matching component by extensionless path or name in `fetchComponents()`, and then calls `fetchComponentContent(component.type, cleanSlug)` [@detail-page].

`fetchComponentContent()` pluralizes the singular component type, reads `public/component-content/{typePlural}/{slug}.json` in development SSR when available, and otherwise fetches the same path from the deployed site with a ten-second timeout [@data-lib]. Failures return an empty string, which keeps the detail page renderable even when the separate content file is missing [@data-lib].

## Invariants And Failure Modes

The main invariant is that index records and content files must agree on slugs. The generator strips `.md` and `.json` from each component path when writing content files, and the detail page uses the same extension-stripped path when calling `fetchComponentContent()` [@catalog-generator] [@detail-page]. If those rules diverge, list pages can still show a component while the detail page loads no body content.

The second invariant is plural type naming for artifact paths. Route types can be singular or plural, but `fetchComponentContent()` writes to plural content paths and `fetchComponentsByType()` expects the plural page type used by the grid [@data-lib] [@type-page]. Failure handling is intentionally user-tolerant: full-index fetches fall back to stale cache when present, per-type fetches return cached data or an empty list, search fetches return cached data or an empty list, and content fetches return an empty string [@data-lib].
