Discord Detailed Notifications Hook for Claude Code: Session Alerts with Duration & Memory

Install a Claude Code hook that posts rich Discord embeds when a session starts and when Claude finishes responding — with project name, duration, and memory usage baked in.

6 min read
Claude Code Hooks Discord Notifications Automation

What is the Discord Detailed Notifications Hook?

The Discord Detailed Notifications hook wires two Claude Code lifecycle events — SessionStart and Stop — to a Discord webhook. Instead of a bare "task finished" ping, it posts rich embeds: which project you're working in, when the session started, and — for the first response after that — how long Claude took and how much memory the process used.

It's a step up from a plain desktop notification hook: the alert lands in a Discord channel you (or your team) already watch, so you can start a long task, tab away, and see exactly when Claude finished without babysitting the terminal.

Installation

Install the hook using the Claude Code Templates CLI:

npx claude-code-templates@latest --hook automation/discord-detailed-notifications
Want to understand how it works? Keep reading to learn what this hook does under the hood and why it's essential for your workflow.

Where is the hook installed?

The hook is saved in .claude/hooks/discord-detailed-notifications.json in your project directory:

your-project/
├── .claude/
│   └── hooks/
│       └── discord-detailed-notifications.json    # ← Hook installed here
├── src/
│   └── components/
├── package.json
└── README.md

You still need a Discord webhook URL for it to actually send anything. Create one from a channel's Settings → Integrations → Webhooks, then export it before starting Claude Code:

export DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/your-webhook-id/your-token"
claude

Without DISCORD_WEBHOOK_URL set, the hook fails safe: SessionStart silently does nothing, and Stop prints ⚠️ Detailed Discord notification skipped: Set DISCORD_WEBHOOK_URL to your terminal instead of erroring out.

How It Works

The component is a plain hooks.json registering two events:

{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup", "hooks": [{ "type": "command", "command": "..." }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "..." }] }
    ]
  }
}
  • SessionStart / matcher "startup" — fires only when a brand-new session launches (Claude Code also supports resume, clear, compact, and fork as matchers for this event, but this hook intentionally ignores those so you don't get a notification every time you resume a chat). The command writes the current Unix timestamp to ~/.claude/session_start.tmp and posts a blue "🚀 Session Started" embed with the project folder name, time, and date.
  • Stop — fires every time Claude finishes responding to a turn, not just when you exit the CLI. On the first Stop after a session starts, the hook reads that timestamp file, computes elapsed seconds, formats it as Xm Ys, samples the Claude Code process's resident memory via ps -o rss=, posts a green "✅ Session Completed" embed — and deletes the timestamp file.
Know the quirk: because the timestamp file is deleted after the first Stop, only your session's first response reports a real duration and memory reading. Every subsequent turn in that same session still fires Stop and still posts an embed, but with Duration: Unknown — it's still telling you Claude finished, just without the elapsed-time math. If you want per-turn timing instead of "time since session start," you'd need to re-write the timestamp file on every Stop rather than deleting it.

Hook commands like this one receive event data as JSON on stdin (fields such as session_id, cwd, and hook_event_name), but this hook only needs shell built-ins — date, basename "$(pwd)", and ps — plus the webhook URL from your environment, so it stays dependency-free.

What You'll See in Discord

Two embeds per session (plus one "Unknown"-duration embed per extra turn):

🚀 Claude Code Session Started
📁 Project: my-app     ⏰ Time: 14:02:11     📅 Date: 2026-09-22

✅ Claude Code Session Completed
📁 Project: my-app     ⏱️ Duration: 4m 12s     💾 Memory Used: 187MB
⏰ Finished: 14:06:23   📅 Date: 2026-09-22

Usage Example

# One-time setup
export DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/.../..."

# Start a session as usual
claude

> Refactor the payment module to use the new retry policy
# ... Claude works, then responds ...
# → "✅ Session Completed" embed lands in Discord with duration + memory

Add export DISCORD_WEBHOOK_URL=... to your shell profile (.zshrc, .bashrc) if you want it active in every terminal, or scope it per-project in a .env file your shell sources before running claude.

Customization Options

The hook is a single JSON file — edit .claude/hooks/discord-detailed-notifications.json directly to change embed colors, add fields (git branch, current model), or point the SessionStart matcher at "*" if you also want a ping on resumed sessions:

{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "*",
        "hooks": [{ "type": "command", "command": "..." }]
      }
    ]
  }
}

Security Notes

  • Never hardcode the webhook URL in the JSON file — keep it in DISCORD_WEBHOOK_URL so it never ends up committed to git.
  • Anyone who obtains the webhook URL can post to your channel. Rotate it from Discord's integration settings if it ever leaks.
  • Hook commands run as ordinary shell commands with your user's permissions — review any hook's command field before installing it, the same way you'd review a shell script.

Key takeaway: This hook turns Claude Code into a good Discord citizen — a startup ping, a real duration on your first response, and an honest "still here, just no timer" on every turn after that.
