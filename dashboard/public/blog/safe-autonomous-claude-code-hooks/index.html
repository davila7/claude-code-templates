Safe Autonomous Claude Code: Combine 3 Security Hooks to Guard Commands, .env Files & Secrets

A practical workflow that layers three PreToolUse hooks from Claude Code Templates: block catastrophic shell commands, protect .env files, and stop secrets before they reach git.

5 min read
Claude Code Hooks Security Workflow Automation

Why Combine Security Hooks?

Letting Claude Code run commands without asking for approval on every step is where the speed is — and where mistakes get expensive. A single bad rm -rf, an overwritten .env, or an API key committed to git can undo hours of work. Hooks are deterministic: they run on every tool call, regardless of what the model decides. Stacking three small PreToolUse hooks gives you layered guardrails.

The Three Components

  • Dangerous Command Blocker (security/dangerous-command-blocker) — a PreToolUse hook on Bash backed by a Python script. It blocks catastrophic commands (rm -rf /, dd, mkfs, fork bombs), protects critical paths like .git/, .claude/ and node_modules/, and warns on suspicious patterns. Blocking uses exit code 2, so Claude sees the reason and adapts.
  • .env File Protection (security/env-file-protection) — a PreToolUse hook on Write that uses the if field (Write(.env*)) so no process is spawned unless the path matches. It returns a deny decision with a clear reason.
  • Secret Scanner (security/secret-scanner) — a PreToolUse hook on Bash that inspects git commits for API keys from 30+ providers, tokens, private keys and database credentials, and blocks the commit with a suggestion to use environment variables.

Installation

Install all three in one command with the Claude Code Templates CLI:

npx claude-code-templates@latest \
  --hook security/dangerous-command-blocker \
  --hook security/env-file-protection \
  --hook security/secret-scanner

The CLI merges each hook's configuration into your project's .claude/settings.json and downloads the supporting scripts into .claude/hooks/:

your-project/
├── .claude/
│   ├── settings.json                      # hooks registered here
│   └── hooks/
│       ├── dangerous-command-blocker.py
│       └── secret-scanner.py
└── .env                                   # now protected from Write
Requirements: the Python-backed hooks call python3, so make sure it is on your PATH. Run /hooks inside Claude Code to confirm all three are registered.

Step-by-Step Workflow

Step 1: Start Claude Code with the guardrails on

cd your-project
claude

Hooks load at session start, so restart Claude Code after installing. Use /hooks to see the three PreToolUse entries.

Step 2: Give Claude an autonomous cleanup task

> Clean up the build artifacts and reset the project config, then commit everything.

Step 3: Watch each layer step in

  • If Claude reaches for something like rm -rf *, the Dangerous Command Blocker exits with code 2 and prints the reason. Claude reads it and retries with a targeted path such as rm -rf dist/.
  • If Claude tries to rewrite .env while "resetting config", .env File Protection denies the Write and tells Claude why.
  • If a hardcoded key sneaks into a file and Claude runs git commit, the Secret Scanner blocks the commit and points to the offending pattern so Claude can move it to an environment variable.

Step 4: Verify with a safe test

Before trusting the setup, ask Claude to run a harmless command that matches a blocked pattern, such as echo test > .env via a Write, and confirm the denial message appears. A guardrail you have not seen fire is a guardrail you cannot rely on.

What Each Hook Covers

RiskHookTool matched
Destructive shell commandsDangerous Command BlockerBash
Overwriting secrets files.env File ProtectionWrite
Leaking keys into git historySecret ScannerBash (git commit)
Heads up: hooks are a safety net, not a sandbox. The .env hook only covers the Write tool, and pattern-based blockers cannot catch every command. Keep real secrets out of the repo, use least-privilege credentials, and pair hooks with Claude Code's permission rules for defense in depth.
